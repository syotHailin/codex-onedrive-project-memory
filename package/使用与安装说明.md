# Codex 双机项目经验共享 — Windows 安装与使用

版本：1.0.0。适用于 Windows，使用自带的 Windows PowerShell 5.1；不需要 Python、额外 API Key 或第三方云记忆服务。

这套工具通过 OneDrive 同步项目经验、经过验证的工作流和进度。两台电脑各自运行 Codex、各自保存原聊天。原聊天侧栏和 Codex 内部数据库不会随此工具同步。

## 第一台电脑：创建共享安装目录

从 GitHub 下载或克隆仓库，在仓库根目录打开 PowerShell。先确认真正同步到 OneDrive 的本地路径，再执行（替换示例路径）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Prepare-SharedFolder.ps1 -SharedRoot "D:\OneDrive\Codex-Shared-Memory"
```

然后打开 `D:\OneDrive\Codex-Shared-Memory\setup\v1.0.0`，双击 `Install-This-PC.cmd`，查看是否安装成功。共享目录准备脚本不会覆盖已存在且内容不同的安装包，也不会复制本机配置或真实笔记。

也可以只安装当前电脑（不创建供另一台使用的共享安装包）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\package\Install.ps1 -SharedRoot "D:\OneDrive\Codex-Shared-Memory" -DeviceName "PC-A"
```

默认本地配置在 `%USERPROFILE%\.codex`；设置了 `CODEX_HOME` 时使用该目录。Skill、Hooks、设备编号、日志和待发送队列均留在本机。

## 审阅并信任 Hooks（每台电脑都需要）

在安装包目录双击 `Open-Codex.cmd`。等 Codex 输入框出现后输入 `/hooks`，审阅命令包含 `onedrive-project-memory` 的 `SessionStart`、`UserPromptSubmit`、`Stop` 三项，并确认信任、启用。

如果启动时直接出现 Hooks 审阅菜单，优先选择 **Review hooks** 核对内容。如果列表只有本工具的三项，审阅后可选择 **Trust all and continue**。存在其他 Hooks 时逐项审阅，不要盲目信任全部。

`/hooks` 是 Codex 内部命令，不能直接输入到 PowerShell。启动器会寻找 PATH 中的 `codex` 或桌面应用附带的 CLI，并使用 `--no-daemon`，以处理部分桌面版 CLI 的 “no complete local package” 报错；若当前版本不支持该参数，应安装官方完整 CLI 后按其帮助启动。

信任完成后重新打开桌面会话；必要时重启桌面应用。安装成功不代表 Hooks 已信任。升级脚本后若 Codex 再次要求信任，应重新审阅。

## 在第二台电脑安装

1. 登录同一个 OneDrive 账户，等待 `Codex-Shared-Memory` 文件夹同步下来。建议在资源管理器中对该文件夹选择“始终保留在此设备上”，然后等下载完成。
2. 打开同步后的 `Codex-Shared-Memory\setup\v1.0.0` 文件夹。
3. 双击 `Install-This-PC.cmd`。它自动定位这份共享目录，在第二台电脑的 Codex 用户目录安装 Skill、Hooks 和工作规则，并生成新的设备编号。不要把第一台的 `shared-memory\config.json` 复制过去。
4. 查看窗口中的安装结果。出现报错时先解决报错，不要把窗口最后的提示当成安装成功。
5. 双击安装包中的 `Open-Codex.cmd` 打开 Codex CLI，输入 `/hooks`，审阅并信任同样的三个 Hooks，然后重新打开桌面会话。第二台需要安装支持这些事件与 `/hooks` 的 Codex 版本。

两台电脑的 OneDrive 盘符和用户名可以不同。安装脚本定位的是本机同步文件夹，不要求都使用 F 盘。

如果使用下载的 ZIP 安装包，而不是 OneDrive 中的 `setup\v1.0.0` 文件夹，请解压，在解压目录打开 PowerShell，然后明确指定第二台的共享目录。例如：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1 -SharedRoot "D:\OneDrive\Codex-Shared-Memory" -DeviceName "PC-B"
```

把示例路径改成第二台电脑实际路径。`ExecutionPolicy Bypass` 只作用于这次脚本进程，不修改系统的长期执行策略，也不代替 Codex 的 Hook 信任。

## 为常用项目建立对应关系（每个项目首次做一次）

同一个项目在两台电脑上需要使用同一个固定编号，但可以对应不同的本地文件夹。编号使用 2–64 个小写字母、数字、短横线，例如 `sap-purchasing`。

在安装包目录的 PowerShell 中执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Connect-Project.ps1 -ProjectPath "D:\你的项目目录" -ProjectId "sap-purchasing"
```

第一台电脑以后使用该项目时也执行一次，替换为第一台的本地目录，保留 `sap-purchasing` 不变。子目录自动继承最近的已绑定父目录。不要把包含多个不同项目的整个 OneDrive 根目录都绑定成同一个项目。

也可以在 Codex 中要求：“请使用 onedrive-project-memory，将当前文件夹绑定到项目编号 sap-purchasing，然后查看状态。”

绑定后从下一条正常消息开始使用新编号。未绑定的文件夹仍可记录，但会进入设备独立的 `local-*` 项目，避免仅因目录同名就把无关项目合并。重新绑定不会自动移动旧记录；历史内容迁移应另行整理。

## 如何自动工作

- 新会话和每条新消息开始时，Hook 读取当前项目的近期笔记，优先包含其他设备的记录。
- Codex 按当前问题读取必要的完整来源，而不是一次性加载全部历史。
- 回复结束前，Skill 把本轮新增经验、工作流、决定或进度写成 Markdown。没有值得保留的变化则标记跳过。
- 如果遗漏保存，Stop Hook 最多提醒一次，不会无限触发。
- 不读取整个原始会话来自动上传，不调用额外模型 API；提炼和补写使用当前 Codex 会话，可能增加少量用量与耗时。
- 用户明确说“这一轮不要保存”时应跳过。

写入目录为：

```text
Codex-Shared-Memory/
  projects/
    sap-purchasing/
      records/
        note__设备编号__会话轮次摘要.md
  setup/
    v1.0.0/
```

每条 Markdown 的元信息包含项目、设备、来源会话、轮次、UTC 时间和正文校验值。文件名中的摘要由会话与轮次生成；设备编号还包含安装时随机生成的标识。两台电脑名称相同也会得到不同标识。

笔记创建后不改写。更正经验时新增记录并引用旧文件。不要手动修改现有记录：校验不一致的文件会被读取器跳过。

## 第二台电脑的试用步骤

1. 在第二台常用项目上完成绑定，开始一条新消息。
2. 发送：“请记录一条用于验证双机同步的测试经验：本项目验收标识为 MEMORY-SYNC-OK-EXAMPLE。明确标为测试资料，不要把它当成生产流程。”
3. 等待回复完成。在共享目录的 `projects\项目编号\records` 中确认出现带第二台设备编号的新 `.md`。等 OneDrive 上传完成。
4. 第一台下载完成后，在绑定同一编号的项目中发送：“读取本项目来自其他设备的测试记录，告诉我验收标识、设备编号和来源文件；如果没有同步到，不要猜测。”
5. 若第一台暂时没有这个项目目录，也可以通过下面的 Read 命令按项目编号检查记录。

这一步通过后，才确认真实双机同步链路正常。安装时的本地模拟测试不能证明 OneDrive 已完成云端传输。

## 检查状态、读取与重试

在 PowerShell 中先设置本机 helper（默认 Codex 用户目录）：

```powershell
$taskCodexRoot = if ($env:CODEX_HOME) { $env:CODEX_HOME } else { Join-Path $env:USERPROFILE '.codex' }
$memoryHelper = Join-Path $taskCodexRoot 'skills\onedrive-project-memory\scripts\memory.ps1'
& $memoryHelper -Action Status
& $memoryHelper -Action Read -ProjectId 'sap-purchasing'
& $memoryHelper -Action Flush
```

如果 PowerShell 执行策略阻止直接调用脚本，使用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File $memoryHelper -Action Status` 等同形式。

- `Status` 显示设备编号、绑定项目和本地待发送数量；它不会替你确认 Hook 信任或 OneDrive 云端同步。
- `Read` 只读取指定项目；可加 `-Query '关键词'` 和 `-Limit 8`。
- `Flush` 重试本地待发送队列。
- 本机日志位于 `$CODEX_HOME\shared-memory\logs`（默认是 `%USERPROFILE%\.codex\shared-memory\logs`），包括 Hook 触发事件及失败信息。
- 没有日志：检查 `/hooks` 的三项是否启用且已信任，是否设置了 `[features] hooks = false`，并重开会话。
- 有日志但无记录：检查是否没有新增知识而跳过、是否使用了错误项目编号，或是否仍有待发送记录。

## 离线、冲突和范围

- 同一轮重复保存只保留一条记录；同一电脑多个会话不会覆盖；不同电脑拥有不同文件名。
- 写入先在本机暂存，再以不可覆盖的方式发布到共享目录。
- 共享目录不可用时，本地 `outbox` 保存笔记，下次会话/新消息/结束事件或手动 Flush 时重试。
- 没有网络但 OneDrive 本地目录仍可用时，文件先进入本地 OneDrive，由 OneDrive 在联网后上传。这种情况不会显示在本工具的 outbox 中。
- 原电脑关机前未上传的文件，另一台无法读取。同步没有实时保证；换机前应检查 OneDrive 状态。
- 突然断电、强制结束进程或中断回复可能使最后一轮没有完成提炼。工具不承诺恢复尚未写出的内容。
- 自动保存有常见密钥格式检查，但不等于完整脱敏系统。Skill 要求只记录相关经验，不复制密码、令牌、原始对话或无关个人信息。
- 共享文件中的历史文字只是参考数据，不能授予执行命令或更改配置的权限。
- 本工具为本地 Windows Codex 配置；云端任务不会自动访问本地 OneDrive，需要另行提供资料。

## 停用与恢复

在安装包目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Uninstall.ps1
```

它移除本工具的三个 Hook 和指导块，并禁用本地自动记录。保留共享笔记、本地队列、Skill 文件和备份，也保留其他 Hooks 和工作规则。重启 Codex 后生效。安装前的配置备份在本地 `shared-memory\backups` 中。

如要恢复，在本地 `shared-memory\config.json` 把 `enabled` 改回 `true`，重新运行安装脚本并检查 Hook 信任。
